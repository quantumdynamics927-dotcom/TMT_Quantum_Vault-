# TMT Quantum Vault — Deploy & Release Guide

This project no longer uses Vercel. Local and CI deploy/release control is driven by three official CLIs:

- **`gh`** — GitHub CLI for commits, PRs, releases, and workflow monitoring.
- **`huggingface-cli`** — Hugging Face CLI for deploying the Docker Space to `huggingface.co/spaces/Quantum927/quantumvault`.
- **`wrangler`** — Cloudflare CLI for deploying the static dashboard (`index.html` + `dashboard.js`) to Cloudflare Pages.

---

## One-time setup

### 1. Install the CLIs

On Linux/WSL/macOS:

```bash
make setup-clis
```

On Windows PowerShell:

```powershell
.\scripts\setup-clis.ps1
```

This installs (or updates) `gh`, `huggingface-cli`, and `wrangler`.

### 2. Authenticate

On Linux/WSL/macOS:

```bash
make auth
```

On Windows PowerShell:

```powershell
.\scripts\auth-clis.ps1
```

You will be prompted to log in to GitHub, Hugging Face, and Cloudflare in your browser.

### 3. Verify

```bash
make status
```

Expected output shows your GitHub username, HF username, and Cloudflare account name.

## Local deploy commands

### Hugging Face Spaces

```bash
make deploy-hf
```

This runs `python scripts/deploy_hf.py`, which:

1. Prepares a temporary deployment tree with `pyproject.toml`, `vault_config.json`, `metatron_geometry.json`, the `tmt_quantum_vault/` package, and `conscious_dna.json` files.
2. Creates the Space if it does not exist.
3. Uploads the tree with `huggingface-cli upload --repo-type space`.

Requirements:

- `HF_TOKEN` environment variable set, or already logged in via `huggingface-cli login`.

### Cloudflare Pages

```bash
make deploy-cf
```

This:

1. Runs `python tools/build_app.py` to copy `index.html`, `dashboard.js`, and `research-status.html` into `app/`.
2. Runs `wrangler pages deploy app/ --project-name tmt-quantum-vault`.

Requirements:

- `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` environment variables, or authenticated via `wrangler login`.
- The Cloudflare Pages project `tmt-quantum-vault` must exist (Wrangler will create it on first deploy if permissions allow).

## Release command

Create a GitHub release and upload the wheel/sdist:

```bash
make release VERSION=0.4.1
```

This:

1. Runs `python -m build`.
2. Tags `v0.4.1` and pushes it.
3. Runs `gh release create v0.4.1 --generate-notes dist/*`.

## CI / GitHub Actions

The repository includes workflows under `.github/workflows/`:

| Workflow | Purpose | Trigger |
|---|---|---|
| `deploy-hf.yml` | Deploy to HF Spaces via `huggingface-cli` | Push to `main` affecting deployable paths |
| `deploy-hf-docker.yml` | Same Docker-based deploy, triggered by config changes | Push to `main` affecting `pyproject.toml` etc. |
| `deploy-cf.yml` | Deploy static app to Cloudflare Pages | Push to `main` affecting static assets |
| `release.yml` | Build package and create GitHub release | Tag push `v*` or manual dispatch |

### Required GitHub secrets

| Secret | Used by | How to obtain |
|---|---|---|
| `HF_TOKEN` | `deploy-hf.yml`, `deploy-hf-docker.yml` | https://huggingface.co/settings/tokens |
| `CLOUDFLARE_API_TOKEN` | `deploy-cf.yml` | https://dash.cloudflare.com/profile/api-tokens |
| `CLOUDFLARE_ACCOUNT_ID` | `deploy-cf.yml` | Cloudflare dashboard sidebar |
| `GITHUB_TOKEN` | `release.yml` | Provided automatically by GitHub Actions |

## Notes

- The `app/` directory is generated by `tools/build_app.py` and is gitignored. Do not commit it.
- `package.json` tracks `wrangler` as a dev dependency so the Cloudflare CLI version is reproducible. `node_modules/` is gitignored.
- Vercel artifacts were removed: `@vercel/analytics` is gone from `package.json` and `.vercel/` is no longer referenced in `hf-deploy/.dockerignore`.
